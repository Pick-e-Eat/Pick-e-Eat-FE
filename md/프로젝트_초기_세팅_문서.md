## 프로젝트 개요
- 스터디용 MVP 서비스의 프론트엔드 애플리케이션
- 단순 CRUD 기반이지만, 현대적인 Atomic Design 아키텍처를 적용
- 예시 도메인: "posts" (게시글) - 이걸 기반으로 다른 도메인도 같은 패턴으로 확장 가능하게
- 백엔드 API: FastAPI (RESTful, /api/v1/posts)

## 기술 스택 및 채택 이유

### Core
- React 19 + TypeScript 5
  → 채택 이유: 생태계 최대, 취업/실무 범용성. TS는 컴파일 타임 안전성 확보
- Vite 6
  → 채택 이유: CRA 대비 10~100배 빠른 HMR. ESBuild 기반으로 대규모에서도 빠름
- React Router v7
  → 채택 이유: 파일 기반 라우팅 없이도 유연한 라우트 설계. Loader/Action 패턴 학습 가치

### 상태 관리
- Zustand
  → 채택 이유: Redux 대비 보일러플레이트 90% 감소. 러닝커브 최소.
    Flux 패턴 학습하면서도 가볍게 시작 가능.
    devtools 미들웨어로 디버깅 지원.
    번들 사이즈 ~1KB로 MVP에 적합
- TanStack Query (React Query) v5
  → 채택 이유: 서버 상태와 클라이언트 상태의 분리라는 현대적 패러다임 학습.
    캐싱, 재검증, 낙관적 업데이트를 선언적으로 처리.
    Zustand는 클라이언트 UI 상태만, 서버 데이터는 TanStack Query가 담당

### UI
- shadcn/ui + Tailwind CSS v4 + Radix UI
  → 채택 이유: 컴포넌트를 node_modules가 아닌 프로젝트 내부에 복사하는 방식.
    완전한 커스터마이징 가능. 블랙박스 없음.
    Radix UI 기반으로 접근성(a11y) 기본 내장.
    Tailwind v4는 설정 파일 없이 CSS 기반 설정(더 간결)

### 폼 & 검증
- React Hook Form + Zod
  → 채택 이유: 비제어 컴포넌트 기반으로 리렌더 최소화.
    Zod 스키마를 백엔드 Pydantic과 유사한 방식으로 정의 → 풀스택 일관성.
    zodResolver로 선언적 폼 검증

### HTTP 클라이언트
- Ky (또는 Axios)
  → 채택 이유: fetch API 래퍼로 인터셉터, 리트라이, JSON 자동 파싱 지원.
    Axios 대비 번들 사이즈 1/3. 모던한 API.
    TanStack Query의 queryFn에 깔끔하게 통합

### 개발 도구
- Biome (린터/포매터)
  → 채택 이유: ESLint + Prettier를 하나로 통합. Rust 기반으로 25배 빠름.
    설정 파일 하나로 통일. 최신 트렌드
- Storybook (선택)
  → 채택 이유: Atomic 컴포넌트를 독립 환경에서 개발/문서화. 디자인 시스템 학습

## 핵심 설계 원칙 & 컨벤션

### 1. Atomic Design 경계 규칙

각 계층은 명확한 책임과 제약을 가진다:

| 계층      | 위치                                  | 역할                                | 제약                                                 |
| --------- | ------------------------------------- | ----------------------------------- | ---------------------------------------------------- |
| Atoms     | components/atoms/ 또는 components/ui/ | 최소 UI 단위 (버튼, 인풋, 뱃지)     | 다른 컴포넌트를 import하지 않음. props만으로 동작    |
| Molecules | components/molecules/                 | Atom 조합 (검색바, 다이얼로그)      | Atom만 조합. 자체 상태 최소화                        |
| Organisms | components/organisms/                 | Molecule+Atom 조합 (헤더, 사이드바) | 레이아웃 섹션 단위. 도메인 로직 없음                 |
| Templates | components/templates/                 | 페이지 레이아웃 뼈대                | children으로 콘텐츠를 받음. 데이터 페칭 없음         |
| Pages     | pages/                                | 라우트 진입점                       | Template + Feature 컴포넌트 조합. 데이터 페칭 시작점 |

핵심 규칙:
- components/ 하위는 도메인을 모른다 (post, user 같은 단어가 들어가면 안 됨)
- 도메인 전용 컴포넌트는 features/{domain}/components/ 에 위치
- shadcn/ui 컴포넌트(components/ui/)는 Atom 취급. 직접 수정 가능하지만 최소화

### 2. 상태 관리 분리 전략

"서버 상태"와 "클라이언트 상태"를 명확히 구분:

```typescript
// ✅ 서버 상태 → TanStack Query (features/posts/api/posts.queries.ts)
// DB에서 오는 데이터: 게시글 목록, 상세 정보
export const usePostsQuery = (params: PostListParams) =>
  useQuery({
    queryKey: ['posts', params],
    queryFn: () => postsApi.getAll(params),
  });

export const useCreatePostMutation = () =>
  useMutation({
    mutationFn: postsApi.create,
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ['posts'] });
    },
  });

// ✅ 클라이언트 상태 → Zustand (features/posts/stores/posts.store.ts)
// UI에서만 존재하는 상태: 필터 조건, 선택된 항목, 모달 열림/닫힘
interface PostsUIState {
  filters: PostFilters;
  selectedPostIds: Set<number>;
  isCreateModalOpen: boolean;
  setFilters: (filters: Partial<PostFilters>) => void;
  togglePostSelection: (id: number) => void;
  openCreateModal: () => void;
  closeCreateModal: () => void;
}

export const usePostsStore = create<PostsUIState>()(
  devtools((set) => ({
    filters: { search: '', isPublished: undefined },
    selectedPostIds: new Set(),
    isCreateModalOpen: false,
    setFilters: (filters) =>
      set((state) => ({ filters: { ...state.filters, ...filters } })),
    togglePostSelection: (id) =>
      set((state) => {
        const next = new Set(state.selectedPostIds);
        next.has(id) ? next.delete(id) : next.add(id);
        return { selectedPostIds: next };
      }),
    openCreateModal: () => set({ isCreateModalOpen: true }),
    closeCreateModal: () => set({ isCreateModalOpen: false }),
  }), { name: 'posts-ui' })
);
```

분리 기준:
- "새로고침하면 서버에서 다시 받아올 데이터인가?" → TanStack Query
- "브라우저 탭에서만 의미 있는 UI 상태인가?" → Zustand
- 서로 절대 섞지 않는다

export const apiClient = ky.create({
  prefixUrl: import.meta.env.VITE_API_BASE_URL,
  hooks: {
    beforeRequest: [
      (request) => {
        const token = localStorage.getItem('token');
        if (token) request.headers.set('Authorization', `Bearer ${token}`);
      },
    ],
    afterResponse: [
      async (_request, _options, response) => {
        if (response.status === 401) {
          // 토큰 만료 처리
        }
      },
    ],
  },
});

// Layer 2: features/posts/api/posts.api.ts (도메인별 API 함수)
import { apiClient } from '@/shared/api/client';
import type { Post, PostCreate, PostUpdate, PaginatedResponse } from '../types/post.types';

export const postsApi = {
  getAll: (params: PostListParams) =>
    apiClient.get('api/v1/posts', { searchParams: params }).json<PaginatedResponse<Post>>(),

  getById: (id: number) =>
    apiClient.get(`api/v1/posts/${id}`).json<Post>(),

  create: (data: PostCreate) =>
    apiClient.post('api/v1/posts', { json: data }).json<Post>(),

  update: (id: number, data: PostUpdate) =>
    apiClient.patch(`api/v1/posts/${id}`, { json: data }).json<Post>(),

  delete: (id: number) =>
    apiClient.delete(`api/v1/posts/${id}`).json<void>(),
} as const;

### 5. Zustand Store 컨벤션

```typescript
// ✅ 권장 패턴
// 1. Store당 하나의 파일
// 2. interface로 State + Actions 타입 정의
// 3. devtools 미들웨어 항상 적용
// 4. selector로 필요한 상태만 구독 (리렌더 최적화)

// 사용 시:
// ❌ Bad: 전체 store 구독 → 어떤 상태가 바뀌어도 리렌더
const store = usePostsStore();

// ✅ Good: 필요한 상태만 selector로 구독
const filters = usePostsStore((s) => s.filters);
const setFilters = usePostsStore((s) => s.setFilters);

// 5. 여러 값을 가져올 때는 useShallow 사용
import { useShallow } from 'zustand/react/shallow';

const { filters, setFilters } = usePostsStore(
  useShallow((s) => ({ filters: s.filters, setFilters: s.setFilters }))
);

// React Router의 errorElement 또는 ErrorBoundary 활용
// TanStack Query의 isPending, isError 상태를 일관되게 처리

// shared/components에 공통 상태 컴포넌트:
// - LoadingSpinner (Atom)
// - EmptyState (Molecule)
// - ErrorFallback (Molecule)

// 페이지 레벨에서 일관된 패턴:
export function PostListPage() {
  const filters = usePostsStore((s) => s.filters);
  const { data, isPending, isError, error } = usePostsQuery(filters);

  if (isPending) return <LoadingSpinner />;
  if (isError) return <ErrorFallback error={error} />;
  if (!data?.items.length) return <EmptyState message="게시글이 없습니다" />;

  return (
    <BaseLayout>
      <PostFilters />
      <PostList posts={data.items} total={data.total} />
    </BaseLayout>
  );
}
```
