# 2026-03-21: Tailwind v4와 CSS Modules 통합 및 최적화

오늘의 작업에서는 Tailwind CSS v4 기반의 프로젝트에 SCSS/CSS Modules를 도입하며 발생한 충돌 문제와 그에 대한 최종 해결 방안을 도출했습니다.

## 1. 주요 문제 상황
- **Sass와 @import 충돌**: Tailwind v4의 `@import "tailwindcss";` 구문이 Sass(Dart Sass)의 `@import` 폐기 경고(Deprecation Warning)와 충돌함.
- **@apply 인식 실패**: CSS Modules(`.module.scss`, `.module.css`) 파일 내부에서 `@apply`를 사용할 때, Tailwind 엔진이 해당 파일을 자신의 처리 대상으로 인식하지 못해 "Unknown utility class" 에러 발생.
- **커스텀 테마 인식 실패**: 기본 테마 외에 프로젝트에서 정의한 `primary`, `accent` 등의 커스텀 색상을 CSS Modules 내에서 `@apply`로 쓰지 못하는 문제 발생.

## 2. 해결 시도 및 분석
1. **@import 수동 추가**: 작동은 하지만 Sass 경고가 발생하고, 모든 모듈 파일마다 Tailwind 베이스 코드가 중복 주입되어 CSS 용량이 비대해짐.
2. **Vite additionalData 설정**: 1번과 동일하게 중복 코드 문제와 Sass 경고 강제 무시 설정(`silenceDeprecations`)이 필요함.
3. **글로벌 CSS 변수 사용**: `@apply` 없이 `var(--color-primary)` 등으로 직접 참조하는 방식. 가장 깔끔하지만 Tailwind의 유틸리티성(`hover:`, `bg-primary/10` 등)을 한 줄로 쓰지 못하는 불편함이 있음.

## 3. 최종 해결 방안: `@reference` 지시어 도입
Tailwind v4의 공식 권장 방식인 **`@reference`**를 사용하여 모든 문제를 해결했습니다.

### 핵심 메커니즘
- **`@reference "tailwindcss";`**: Tailwind의 모든 유틸리티 규칙을 "지식으로만 참조"하고, 실제로 코드를 생성(중복 주입)하지는 않음.
- **`@reference "@/styles/globals.css";`**: 우리 프로젝트에서 `@theme` 블록으로 정의한 모든 커스텀 색상과 설정까지 인식하게 함.

### 앞으로의 개발 규칙 (Golden Rule)
1. **파일 구성**: 각 컴포넌트/페이지별로 `.tsx`와 같은 위치에 `.module.css` (또는 SCSS) 파일 생성.
2. **참조 추가**: 파일 최상단에 `@reference "../../../styles/globals.css";` (경로 주의) 한 줄 추가.
3. **스타일링**: `@apply`를 사용하여 Tailwind의 편리함과 SCSS의 강력한 제어력을 충돌 없이 동시에 활용.

## 4. 성과
- **Sass 경고 해결**: 더 이상 전역에서 `@import` 충돌 걱정 없이 작업 가능.
- **빌드 최적화**: 중복 코드 없이 필요한 유틸리티만 효율적으로 추출되어 빌드 결과물이 가벼워짐.
- **유지보수성 향상**: TSX에는 로직만, CSS/SCSS에는 스타일 명세만 두어 코드 응집도 높임.
