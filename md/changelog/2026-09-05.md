# 2026-09-05: 익명 클라이언트 식별(X-Client-Id) 연동

로그인 없이도 사용자의 기기/브라우저를 일관되게 식별하여 스와이프 판단(Like/Nope) 및 개인화 추천이 연속적으로 유지될 수 있도록 `ky` HTTP 클라이언트 인터셉터를 구축했습니다.

---

## 1. 도입 배경
- **목적**: 로그인 진입 장벽 없이 누구나 즉시 식당 추천 카드를 스와이프할 수 있도록 지원.
- **하드웨어 식별자(MAC 주소) 사용 불가**:
  - 웹 브라우저 샌드박스 정책 및 모바일 OS 프라이버시 보호(난수화) 정책으로 인해 웹/앱에서 실제 MAC 주소 접근 불가능.
- **채택된 방식**:
  - 클라이언트 로컬 스토리지에 무작위 `UUID v4` 발급 및 보관.
  - 모든 API 요청 시 `X-Client-Id` 헤더로 서버에 전달하고, 백엔드는 이를 `SHA-256(salt)` 단방향 해싱하여 DB에 안전하게 보관.

---

## 2. 주요 변경 사항

### 2.1. HTTP 클라이언트 인터셉터 설정 (`src/shared/api/client.ts`)
1. **`getOrCreateClientId()` 유틸 함수 구현**:
   - `localStorage.getItem("pick_client_id")` 확인.
   - 존재하지 않으면 `crypto.randomUUID()`로 새 UUID를 발급하여 로컬 스토리지에 저장.
2. **`beforeRequest` 훅 (요청 헤더 자동 주입)**:
   - 모든 API 요청 헤더에 자동으로 주입:
     - `X-Client-Id`: `[UUID v4]`
     - `X-Platform`: `"web"`
3. **`afterResponse` 훅 (서버 발급 동기화)**:
   - 서버 응답 헤더에 `x-client-id`가 포함되어 있고 로컬과 다를 경우 최신 상태로 동기화.

---

## 3. 개발 및 연동 참고사항
- **컴포넌트 수정 불필요**: `apiClient`를 사용하는 모든 API 모듈(`restaurantAPI` 등)에 자동으로 헤더가 실려 나가므로, 개별 페이지나 컴포넌트 레벨에서의 추가 작업은 전혀 없습니다.
- **초기화 시점**: 브라우저 스토리지를 비우거나(시크릿 모드 등) 다른 브라우저로 접속하면 새로운 익명 유저로 분리되어 신선한 카드가 추천됩니다.
